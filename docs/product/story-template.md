# Story template

Copy this into the [story backlog](user-stories.md). A small story needs only enough
detail to agree the outcome and test it; split unrelated outcomes into separate stories.

## US-XX — Short outcome-oriented title

**Status:** Draft  
**Release:** Unassigned  
**Actor:** Coach / client / other agreed role

**Story:** As a …, I want …, so that … .

**Context / real example:** When does this happen? What does the person do today?

**Acceptance scenarios — proposed until agreed:**

- **Given** … **when** … **then** … .
- Failure or exception: … .
- Recovery: … .

**Rules / permissions:** Who can do this, to whose data, and in which state?

**Current evidence:** Source reference, synthetic test, live observation, or none.
Do not equate current implementation with agreed acceptance criteria.

**Open questions:** Link Q-XX, or add a question.

**Out of scope for this story:** Only exclusions that have actually been agreed.

**Decision record:** Date · participants · decision · rationale.

**Verification when implemented:** Which acceptance scenarios run locally/in CI?
Which still need a real backend or a user walkthrough?
